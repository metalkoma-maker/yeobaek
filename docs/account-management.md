# 계정 찾기·비밀번호·탈퇴

현재 로그인 아이디는 이메일 주소다. 로그인 화면에는 별도의 아이디 찾기 버튼을 두지 않는다. 기존 아이디 찾기 API는 입력한 이메일로 가입 여부와 로그인 이메일을 알리며, 웹 응답에는 계정 존재 여부를 드러내지 않는다.

분실 비밀번호 재설정은 이메일로 일회용 링크를 보낸다. 토큰 원문은 DB에 저장하지 않고 SHA-256 해시만 저장하며 30분 후 만료된다. 링크에는 URL 조각(`#reset=...`)을 사용해 토큰이 웹 서버 요청 경로와 참조 주소에 포함되지 않도록 한다. 재설정에 성공하면 그 계정의 모든 세션과 남은 재설정 토큰을 없앤다. 로그인한 상태의 비밀번호 변경은 현재 비밀번호를 요구하고, 다른 기기의 세션을 없앤 뒤 현재 기기에 새 세션을 준다. 요청 횟수는 이메일·접속 IP별로 제한한다.

운영 로그인 화면의 비밀번호 찾기 버튼은 메일 발송 설정과 실제 발송 검증이 끝날 때까지 숨긴다. 서버의 복구 API와 받은 링크를 처리하는 화면은 향후 활성화를 위해 유지한다.

운영 메일 발송에는 서비스 환경 변수 `SMTP_HOST`, `SMTP_FROM`, `APP_PUBLIC_URL`(예: `https://example.com`)이 필요하다. SMTP 인증이 필요하면 `SMTP_USERNAME`과 `SMTP_PASSWORD`를 함께 설정한다. 기본 연결은 TLS가 적용된 포트 465다. STARTTLS 제공자는 `SMTP_SECURITY=starttls`, `SMTP_PORT=587`을 사용한다. 비밀 값은 Git에 넣지 않는다. 이 설정이 없으면 찾기·분실 복구 API는 503을 반환하며 메일을 보낸 것처럼 표시하지 않는다. 실제 발송은 운영 반영 전에 별도 주소로 검증해야 한다.

탈퇴는 현재 비밀번호와 `탈퇴` 문구를 요구한다. 삭제 직전 계정·모든 원고·수정 이력·복원 지점의 영구 삭제를 다시 알리는 확인창을 띄우며, 취소하면 삭제 요청을 보내지 않는다. 확인하면 운영 DB에서 계정, 원고, 수정 이력, 복원 지점, 통계, 세션이 외래키 연쇄 삭제된다. 브라우저의 해당 이메일에 연결된 임시 글도 삭제한다. 관리자 계정은 관리자 설정 파일에 ID가 고정돼 있어 화면에서 탈퇴할 수 없다. 서버 로컬 자동 백업은 7일 경과 후 정리하지만, Google Drive 백업과 배포 전 스냅샷의 보존 기간은 이 코드만으로 확정할 수 없다. 운영 백업 스크립트는 개발 환경에서 실행하지 않는다.

검증은 합성 계정과 임시 DB, 모의 메일 발송만 사용한다. 운영 회원·원고·백업은 테스트에 사용하지 않는다.
웹 미리보기의 상단 `테스트 메일함`은 가짜 계정 `mobile-test@example.com`으로 보낸 안내만 메모리에 보여준다. 외부 SMTP에 연결하지 않으며 미리보기 서버 종료 시 메일함과 DB가 함께 사라진다.
