# 원고 복원 지점

이 기능은 기존 `manuscript_history`의 최근 50개 수정 이력을 그대로 유지하면서,
오래 남길 복원 지점을 `manuscript_checkpoints`에 별도로 저장한다.

- 자동 복원 지점: 첫 저장 이후의 버전부터 만들며, 마지막 복원 지점에서 30분이 지났거나 이전 저장 후 30분이 지난 상태에서 새로 저장할 때 이전 글을 담는다. 최신 10개, 최근 30일의 하루당 1개, 최근 12개월의 월당 1개를 남긴다.
- 중요 버전: 사용자가 현재 글이나 이력의 버전에 이름을 붙인다. 자동 정리 대상에서 제외한다.
- 기존 이력: 최초 실행 시 기존의 최근 수정 이력을 한 번만 복원 지점으로 복사한다. 원본 이력과 현재 원고는 변경하지 않는다. 이미 이전 정책으로 삭제된 이력은 복구할 수 없다.
- 복원 전 글: 사용자가 복원하면 직전 글을 별도 복원 지점에 남기고 선택한 버전을 새 버전으로 저장한다. 다른 기기에서 원고를 변경했다면 409를 반환하고 아무것도 덮어쓰지 않는다.

`schema_migrations`의 `history_checkpoints_v1` 표식과 기존 이력 복사는 하나의 SQLite 트랜잭션으로 처리한다. 두 테이블의 추가와 이력 복사는 앱 시작 시 수행하며, 배포 전 DB 스냅샷과 기존 파일 백업을 유지해야 한다. 코드 복원은 앱 파일만 되돌린다. 새로 추가된 테이블과 기존 원고 데이터는 자동으로 삭제하거나 이전 상태로 되돌리지 않는다. 이전 앱 코드는 추가된 테이블을 읽지 않는다.

검증에는 임시 가짜 DB와 브라우저의 가짜 API를 사용한다. 운영의 회원, 원고, 수정 이력, 백업은 개발 테스트에 사용하지 않는다.
