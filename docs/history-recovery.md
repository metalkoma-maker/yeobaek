# 원고 복원 지점

이 기능은 기존 `manuscript_history`의 최근 50개 수정 이력을 그대로 유지하면서,
오래 남길 복원 지점을 `manuscript_checkpoints`에 별도로 저장한다.

- 자동 복원 지점: 첫 저장 이후의 버전부터 만든다. 앱·웹 화면을 떠날 때 현재 저장된 글을 남기고, 집필 중에는 마지막 복원 지점에서 약 30분이 지났거나 마지막 저장 후 10분 이상 쉰 뒤 다시 저장할 때 이전 글을 담는다. 최신 10개, 최근 30일의 하루당 1개, 최근 12개월의 월당 1개를 남긴다.
- 별도 보관 버전: 서버는 이름 붙여 보관한 버전을 자동 정리 대상에서 제외한다. 현재 웹 화면은 최근·예전 수정 이력 두 탭만 제공한다.
- 기존 최근 수정 이력은 최근 50개 목록에서만 보여 준다. 예전 수정 이력 기능을 도입할 때 복사했던 `legacy` 행은 운영 DB에 그대로 두지만, 목록·복원 API에서는 제외한다. 새로 설치하는 서버는 이 복사본을 만들지 않는다. 원본 이력과 현재 원고는 변경하지 않는다.
- 복원 전 글: 사용자가 복원하면 직전 글을 별도 복원 지점에 남기고 선택한 버전을 새 버전으로 저장한다. 다른 기기에서 원고를 변경했다면 409를 반환하고 아무것도 덮어쓰지 않는다.

`schema_migrations`의 `history_checkpoints_v1` 표식은 앱 시작 시 기록한다. 배포 전 DB 스냅샷과 기존 파일 백업을 유지해야 한다. 코드 복원은 앱 파일만 되돌린다. 이전 배포에서 생성된 `legacy` 행이나 기존 원고 데이터는 자동으로 삭제하거나 이전 상태로 되돌리지 않는다.

검증에는 임시 가짜 DB와 브라우저의 가짜 API를 사용한다. 운영의 회원, 원고, 수정 이력, 백업은 개발 테스트에 사용하지 않는다.
