# 약관·개인정보처리방침 작성에 참고할 기술 사실

확인일: 2026-10-25. 기준 코드: `8d73b0613d1a53f2ac1850185243ceae4c7588e1`.
이 문서는 현재 코드와 사용자 확인 결과를 정리한 자료다. 법률 판단이나 이용자에게 그대로 게시할 약관 문안은 아니다. 운영 서버 설정·백업 실행 상태처럼 확인하지 못한 사항은 아래에 따로 적었다.

## 코드에서 확인한 내용

- 가입 아이디는 이메일 주소다. 서버 DB에는 이메일과 비밀번호의 무작위 소금값·`scrypt` 해시를 저장한다. 원문 비밀번호를 DB에 저장하는 코드는 없다. 현재 가입 화면과 가입 API에는 이메일 소유 확인이나 약관 동의 기록 절차가 없다. 근거: [앱 서버](../app.py), [가입 화면](../static/index.html).
- 계정과 연결된 원고 제목·본문, 최근 수정 이력, 예전 복원 지점, 일별 글자 수, 원고 순서, 로그인 세션과 비밀번호 재설정 토큰 정보가 SQLite에 저장된다. 로그인·복구 요청의 횟수 제한 기록은 IP·이메일 조합 등을 해시한 키, 시각, 횟수로 별도 저장된다. 원고와 이력은 종단 간 암호화되어 있지 않으며 서버 운영자는 기술적으로 내용을 읽을 수 있다. 근거: [DB 구조와 요청 제한](../app.py), [프로젝트 지침](../AGENTS.md).
- 원고의 최근 수정 이력은 이전 버전 50개를 유지한다. 예전 복원 지점은 화면을 떠날 때, 집필 중 약 30분마다, 쉬었다 다시 저장할 때 남기며 자동 정리 기준이 따로 있다. 다른 기기와 수정이 충돌하면 서버는 `409`를 반환해 조용히 덮어쓰지 않는다. 브라우저의 임시 글 보관과 TXT 내려받기 기능도 있다. 이 기능들은 원고 유실 위험을 낮추는 장치이며 무손실을 보장한다는 근거는 아니다. 근거: [원고 복원 설명](history-recovery.md), [앱 코드](../app.py), [웹 코드](../static/app.js).
- 비밀번호 재설정 메일은 SMTP로 보낸다. 현재 최초 설정 도구는 전용 Gmail의 SMTP를 사용하고, 앱 비밀번호는 Git이 아닌 서버의 root 전용 설정 파일에 기록한다. 메일 서비스로 수신자 주소, 제목과 재설정 링크가 담긴 본문이 전달된다. 발신 Gmail 주소는 수신 메일의 `보낸 사람`에 나타난다. 재설정 토큰 원문 대신 SHA-256 해시를 DB에 저장하며 링크는 30분 후 만료된다. 성공적으로 재설정하면 기존 로그인 세션과 남은 재설정 토큰을 삭제한다. 근거: [메일·재설정 코드](../app.py), [Gmail 설정 도구](../deploy/configure_gmail_recovery.py).
- 회원 탈퇴 시 현재 비밀번호·`탈퇴` 확인 문구와 마지막 경고가 필요하다. 실행되면 운영 DB의 계정 및 연결된 원고·이력·복원 지점·통계·세션이 연쇄 삭제된다. 현재 브라우저에 해당 이메일로 남긴 임시 글도 삭제한다. **이미 만들어진 백업 파일과 계정에 외래키로 연결되지 않은 요청 횟수 제한 기록은 이 API에서 삭제되지 않는다.** 근거: [탈퇴 API와 요청 제한 기록](../app.py), [탈퇴 화면](../static/app.js), [계정 관리 문서](account-management.md).
- [서버 로컬 자동 백업 스크립트](../backup.py)는 실행할 때 7일이 지난 해당 백업 파일을 정리한다. [Google Drive 백업 스크립트](../backup_drive.py)는 지정된 이름의 백업을 업로드·재다운로드해 검사하고, 실행할 때 30일이 지난 해당 원격 파일을 정리한다. 스크립트에 적힌 기간은 실제 예약 실행·저장소 정책이 정상 작동했음을 증명하지 않는다.
- [배포 도구](../deploy/actions_gateway.py)는 배포 전에 DB 스냅샷과 코드 백업을 만든다. 검토한 배포 도구에는 이 스냅샷을 기간에 따라 자동 삭제하는 코드가 없다. 코드 복원은 DB 전체를 이전 시점으로 되돌리지 않는다. 근거: [배포 설명](manual-web-deployment.md).
- [기존 Google Drive 안내](../static/backup-privacy.html)는 운영자의 Drive 백업 연결에 관한 별도 문서다. 일반 회원 가입용 개인정보처리방침으로 사용하기 전에 제목·범위·연락처와 현재 운영 상태를 따로 확인해야 한다.

## 운영 과정에서 별도로 확인된 내용

- 2026-10-24 사용자가 전용 Gmail의 시험 메일 수신, 운영 로그인 화면의 비밀번호 찾기 버튼 표시, 가입된 주소로 보낸 재설정 메일 수신을 확인했다. 메일 설정 도구는 서비스 재시작과 비밀번호 찾기 API 응답 확인 후 `메일 설정 완료`를 출력했다. 재설정 링크를 이용해 운영 계정의 비밀번호를 실제 변경하는 시험까지 했다는 뜻은 아니다.

## 문안 확정 전에 운영자가 확인할 사항

- 사업자 명칭, 담당자·문의 주소, 가입 약관 동의를 받는 방식과 동의 이력을 저장할 방법.
- 로컬·Google Drive 백업의 실제 예약 실행, 최근 성공 기록, 공유·접근 권한과 파일 삭제 결과.
- 배포 전 DB 스냅샷의 실제 보관·수동 삭제 정책. 탈퇴 후 백업에 남은 정보가 언제 최종 삭제되는지 현 코드만으로 보장할 수 없다.
- 요청 횟수 제한 기록의 삭제 주기. 현재 앱 코드에서는 오래된 기록을 정리하는 작업을 찾지 못했다.
- Gmail·Google Drive 이용과 관련해 공지해야 할 처리 항목·위탁·국외 이전 여부 등 법률 문안은 별도 법률 검토가 필요하다.

## 비밀번호 규칙 검토 메모

- 현재 [서버의 가입·변경·재설정 규칙](../app.py)은 10~256자이며 대문자·숫자·특수문자 조합을 강제하지 않는다. 로그인 시도와 복구 메일 요청에는 횟수 제한이 있다. 흔하거나 유출된 비밀번호를 거르는 검사는 현재 없다.
- [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html)와 [OWASP 인증 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)는 단일 비밀번호 인증에 15자 이상, 흔하거나 유출된 비밀번호 차단, 공백·유니코드·비밀번호 관리자의 허용을 권한다. 문자 종류 조합과 정기 변경을 강제하지 말라고 한다. 이는 참고 기준이지 현재 소설여백에 적용된 규칙이나 한국 법령의 의무라는 뜻이 아니다.
- 구현을 결정한다면 신규 가입·비밀번호 변경·재설정에 새 기준을 적용하고, 기존 회원이 현재 비밀번호로 로그인할 수 있도록 로그인 검증과 변경 시점을 구분해야 한다.
