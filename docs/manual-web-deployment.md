# 수동 웹 배포 도구

수동 GitHub Actions로 웹 정적 파일 6개만 배포합니다. 운영 접속 정보는 공개 코드에 포함하지 않습니다. 최초 서버 설치 패키지와 Windows 상세 안내서는 별도로 전달합니다. 이 변경의 병합은 운영 배포를 실행하지 않습니다.

## 운영 코드 보존

사용자가 제공한 코드 해시와 작업 공간을 대조했습니다. 대상 21개 코드 파일이 일치했고, 당시 main과 웹 파일 6개가 달랐습니다. 이 변경에 해당 웹 개선본을 함께 포함해 기존 백스페이스 성능 개선·실행 취소/다시 실행·제목 스크롤을 보존합니다. 비교 대상 이외의 설정이나 DB 일치 여부는 판단하지 않습니다. 최초 설치가 실제 서버에서 승인된 해시를 다시 확인해야 합니다.

## 최초 설정

1. 클라우드 콘솔에서 SSH 허용 IP를 확인합니다. 기존 접근 제어를 변경하지 않습니다. GitHub 호스팅 실행기는 IP가 유동적이므로 좁은 허용 범위라면 별도 고정 IP 실행기/VPN 설계가 먼저 필요합니다.
2. 사용자 PC에서 배포 전용 Ed25519 키를 생성합니다. 개인키는 GitHub Environment secret에만 등록하고 서버에는 공개키만 설치합니다.
3. 별도 제공된 설치 패키지로 제한된 배포 계정/강제 명령을 설치합니다. 이 도구는 root 소유 설정 `/etc/yeobaek-actions.json`에서 프로젝트·백업 경로, HTTPS 호스트, 서비스 이름을 읽습니다. SSH 명령으로 설정을 변경할 수 없습니다.
4. GitHub `production` Environment를 만들고 main 브랜치만 허용합니다. 가능하면 필수 검토자를 설정합니다. secret `DEPLOY_SSH_KEY`, variables `DEPLOY_HOST`와 `DEPLOY_KNOWN_HOSTS`를 등록합니다. 호스트 키는 기존 신뢰한 관리자 연결에서 확인합니다.
5. 워크플로를 main에 반영한 뒤 수동 inspect부터 실행합니다. 설치 완료 및 실제 접속 확인 전에는 deploy를 실행하지 않습니다.

## 실행과 복원

Actions → 여백 웹 수동 배포 → Run workflow. 기본 inspect는 코드 조회만 수행합니다. deploy/rollback은 바로 전 inspect의 fingerprint를 요구합니다. 조회 이후 코드가 바뀌면 중단합니다. 원고의 편집은 코드 해시에 영향을 주지 않습니다.

가짜 DB와 Chromium 검증이 먼저 통과해야 서버 작업으로 진행합니다. 배포 파일은 edit-history.js, font-size.js, safety-storage.js, app.js, style.css, index.html입니다. 서버에서는 승인된 배포 제외 코드의 변경 여부까지 확인하고, 웹 파일을 별도 백업한 뒤 소유자/그룹/권한을 보존해 교체합니다. index.html은 마지막에 교체합니다.

서비스 상태와 로컬 Nginx HTTPS를 검사하고 페이지 및 파일의 실제 응답 해시를 확인합니다. 실패 시 원래 웹 파일을 복원하고 복원 후 확인합니다. DB/회원/원고/기존 자동 백업을 읽거나 변경하는 명령은 수행하지 않습니다. 서버 설정 변경이나 서비스 재시작도 하지 않습니다.

수동 rollback은 직전 배포 직전의 파일을 복원합니다. 강제 종료로 pending 기록이 남으면 새 배포를 차단하고 rollback을 요구합니다. 백업 손상/예상하지 못한 코드 변경이 있으면 덮어쓰지 않고 중단합니다. 전용 키는 셸·SFTP·포워딩에 사용할 수 없습니다.

## 검증 및 한계

가짜 서버 폴더에서 성공 배포/백업/권한 보존, 수동 복원, 상태 검사 실패/파일 교체 도중 실패 시 자동 복원, 중단 작업 복구, 백업 손상, 오래된 fingerprint, 배포 제외 코드 변경, ZIP의 DB/경로 탈출/중복 파일, 심볼릭 링크 거부를 검증했습니다. Chromium은 가짜 API만 사용해 한글 조합·붙여넣기·연속 삭제·실행 취소·자동저장·409·복구 B·PC/모바일 스크롤을 확인합니다.

로컬 검증은 실제 서버 SSH/sudo/ACG/TLS 검증을 대신하지 않습니다. 첫 설치/inspect는 별도로 확인해야 합니다. 현재 자동화 범위는 정적 웹 파일이며 Python 코드·의존성·DB 변경은 포함하지 않습니다. 웹 파일 6개의 교체는 각 파일 단위로 수행되며 전체 디렉터리를 한 번에 교체하는 구조는 아닙니다. 이후 코드 작업 동안 수동 서버 파일 수정과 배포를 동시에 하지 않습니다.
